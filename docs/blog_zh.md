# 把 Diffusion LLM 用作单次前向决策模型：一次 40k 监督适配实验

> 研究报告 / 技术博客草稿，2026-09-24。本文报告已完成的初步实验，不是成熟产品的性能承诺，也不主张已经证明 diffusion 架构优于自回归模型。
>
> 主结果使用 **S1 的开发集选优 checkpoint：step 1,300**。它位于第二个 epoch 开始后不久，**不是 epoch 1 结束的 step 1,250**。训练完整运行三轮，随后依据预先固定的 dev KL 规则选模。

## 摘要

许多实际系统并不需要语言模型生成一段长回答，而是需要一个清楚的决策：从若干动作中选择一个、判断一个命题是否成立，或者给出一个有序等级。更进一步，下游系统往往需要的不是答案字符串，而是可用于排序、阈值判断和风险控制的概率分布。

我们尝试将一个约 0.6B 参数的 masked diffusion language model（MDLM），通过统一的 **Shared Yes/No** 读出方式适配为决策模型：为候选项设置 mask，在一次前向中读取每个位置的 Yes/No logits，再转换为结构化概率。

我们先构建了 10k 决策的 S0 数据集，再扩充为 40k 决策的 S1。公共数据沿用已有标注，少量规则、状态和概率任务通过程序验证；没有调用生成式 API 标注、改写或生成伪标签。当前六个外部测试来源及其同源派生数据均被排除在本项目的监督训练数据之外。

主要观察如下：

- **适配有效，但收益依赖任务。** S1 相比原始 MDLM，在 Banking77 上从 24.09% 提高到 60.49%，在 typed-decisions 上从 41.35% 提高到 52.25%；与此同时，Prompt Injection 从 82.76% 下降到 70.69%。
- **扩大数据量不等于全面进步。** S0 与 S1 的六套外部任务等权平均准确率分别为 60.48% 和 60.54%，总体基本持平。
- **准确率与概率质量会分离。** Emotion 上，S1 准确率略高于原始 base，但 ECE 从 7.95% 上升到 23.02%。
- **批处理显著改善吞吐。** 在同一张 RTX A6000、BF16 和相同评测代码下，batch32 的均摊前向耗时为 6.61 ms/decision，相比 batch1 提升约 3.85 倍。这个数字不是单请求延迟，也不是相对于 Laya 或 AR 的架构加速比。

我们的结论不是“得到一个全面更好的模型”，而是：**小型 MDLM 可以被适配为一个有用的通用决策接口；接下来真正困难的是跨任务能力保持与概率可靠性。**

## 1. 我们要解决的，不是开放式文本生成

把语言模型接入一个流程，常见的做法是要求它生成 JSON，或者输出一个类别名。这样的方式很灵活，但也将几个问题混在了一起：理解任务、选择答案、生成合法格式，以及解释输出概率。

我们的实验将输出范围限定为三类决策原语：

| 原语 | 输入和输出 | 一个示意用途 |
|---|---|---|
| `choice` | 给定动态候选列表，输出互斥候选的概率 | 选择下一步操作或识别意图 |
| `noul` | 给定状态和命题，输出 false/true 概率 | 判断条件是否成立 |
| `score` | 给定有序等级，输出等级分布和期望值 | 严重程度、质量或情感等级 |

这里的“动态”指候选项随输入变化，而不是每个任务都拥有一个固定类别的专用分类头。我们希望模型读取自然语言描述后，使用同一个接口处理不同的候选集合。

这也限定了研究目标：本文不评价长文本生成、解释质量、工具调用轨迹或多步规划，不把一次分类决定等同于完整的 agent 能力。

## 2. 方法：用共享的 Yes/No 读出统一决策

### 2.1 在候选项后设置 mask

对 choice 和 score，我们将状态、问题与完整候选描述放入输入，并为每个候选设置一个 mask。下面只是示意，不是测试集样本：

```text
State:
库存剩余 8 件，订单需要 3 件。

Question:
下一步应执行什么操作？

For each option, mark Yes if it answers the question, otherwise No.
直接安排发货: [MASK]
因缺货取消订单: [MASK]
请求补充商品数量: [MASK]
```

实现中 mask 以明确的 token ID 插入，保留在 user message 内；不依赖模型先生成一段 assistant 文本。原始文本若含有特殊 mask token，构建器会检查处理边界，避免把源文本误当作输出槽位。

同一次前向处理一个 decision 的所有候选 mask。Banking77 的 77 个候选不需要分别运行 77 次完整模型。

### 2.2 读取 Yes-minus-No，而不是生成候选名字

在候选 $i$ 对应的位置读取两个词表 logits：

$$
s_i=z_i^{\mathrm{Yes}}-z_i^{\mathrm{No}}.
$$

对于互斥 choice 和 score，跨候选归一化：

$$
p_i=\frac{\exp(s_i)}{\sum_{j=1}^{K}\exp(s_j)}.
$$

对于 noul，只设置一个输出 mask：

$$
P(\mathrm{true})=\sigma\!\left(z^{\mathrm{Yes}}-z^{\mathrm{No}}\right),
\qquad P(\mathrm{false})=1-P(\mathrm{true}).
$$

所有主评测都固定 softmax 温度为 1，不在外部测试集上拟合温度。本文的单次前向和温度 1 是两个不同概念：**没有运行多步 diffusion 采样或迭代去噪。**

这种接口有两个实用优点：候选可以用自然语言描述；不同任务共享同一对 Yes/No 词表行，而不是为任意标签名字单独规定生成格式。它减少了对“生成 A/B/C 字符串”的依赖，但不保证消除候选顺序、描述措辞或 prompt 敏感性。

计算时只对需要的 hidden states 投影到 Yes/No 两行权重，没有为每个位置计算完整词表 logits。

### 2.3 训练目标

choice 和 noul 使用交叉熵。令目标分布为 $q$：

$$
\mathcal L_{\mathrm{CE}}=-\sum_i q_i\log p_i.
$$

大部分公共监督是硬标签；少量概率机制任务使用可计算的真实目标分布，不使用教师模型自报置信度冒充 soft target。

score 除交叉熵外，还加入 normalized Ranked Probability Score（RPS）：

$$
\mathcal L_{\mathrm{score}}=\mathcal L_{\mathrm{CE}}+0.25\,\mathrm{RPS}(p,q),
$$

$$
\mathrm{RPS}(p,q)=\frac{1}{K-1}\sum_{k=1}^{K-1}
\left(\sum_{i=1}^{k}p_i-\sum_{i=1}^{k}q_i\right)^2.
$$

RPS 利用等级顺序区分“偏差一个等级”和“偏差多个等级”。训练损失按 decision 归一化，而不是把候选多的任务直接计作更多独立样本。

## 3. 为什么选择 Diffusion LLM，而不是 AR？

这里的理由是**结构与任务接口的契合**，不是先验认定 diffusion 一定更快或更强。

### 3.1 双向上下文适合多个预设读出位置

在我们的形式中，多个 mask 都应该依据完整状态、问题与候选集合做判断。MDLM 的双向注意力与这种输入形式直接匹配，不需要把候选答案组织为一条依次生成的文本序列。

这尤其适合研究一个问题：当输出是若干离散决策槽位而不是自由文本时，语言模型已有的语义能力能否通过简单监督被重新利用？

### 3.2 我们需要判别分数，不需要生成解释

每个候选的读出位置预先给定，输出词表也只关注 Yes/No。一次前向就能得到候选间可归一化的分数，是这个方法的接口设计目标。

需要避免一个误解：这不是说常规 AR 只能通过长篇生成做分类。AR 模型也可以读取下一个 token 的候选概率、使用分类头，或者通过合理的候选打分实现决策。有些 AR 方案同样只需要一次 prefill 前向。

### 3.3 当前实验不能证明 diffusion 优于 AR

我们尚未完成同规模、同训练数据和预算下的受控 AR 对照。因此，本文不作下列推断：

- diffusion 天然比 AR 分类准确率更高；
- 一次前向是 diffusion 独有的能力；
- batching 加速证明了 diffusion 的架构优势；
- 与 Laya 的比较等价于 diffusion 与 AR 的比较。

Laya 本身就是一个单次前向的决策模型。我们选择它作为有实际意义的发布模型参照，不把它当作“必须生成长答案的 AR 对手”。

## 4. 从 S0 到 S1：扩充什么，而不只是扩充多少？

### 4.1 数据组成

S0 是 10,000 条训练决策，S1 保留合规 S0 train，再增加 30,000 条决策。开发集不计入这些数字。

| 来源或能力 | S0 | S1 新增 | S1 合计 | S1 占比 |
|---|---:|---:|---:|---:|
| CLINC，排除银行/信用卡域 | 2,000 | 3,000 | 5,000 | 12.5% |
| SNLI | 3,000 | 6,000 | 9,000 | 22.5% |
| ARC | 1,000 | 0 | 1,000 | 2.5% |
| SGD | 1,000 | 3,000 | 4,000 | 10.0% |
| DBpedia | 0 | 6,000 | 6,000 | 15.0% |
| GoEmotions 单标签 | 0 | 3,000 | 3,000 | 7.5% |
| BoolQ | 0 | 4,000 | 4,000 | 10.0% |
| 可验证约束/状态任务 | 1,000 | 1,000 | 2,000 | 5.0% |
| 可验证 ordinal 任务 | 1,500 | 3,000 | 4,500 | 11.25% |
| 已知概率机制 | 500 | 1,000 | 1,500 | 3.75% |
| **总计** | **10,000** | **30,000** | **40,000** | **100%** |

S0 是 70% 公共数据转换、30% 程序合成；S1 是 80% 公共数据转换、20% 程序合成。公共标注不等于全部人工标注：例如 DBpedia 使用其已有的本体派生标签，不是本项目调用模型重新标注。

最初的独立评分来源没有锁定，因此采用计划允许的、带明确操作性 rubric 的可验证 ordinal 合成替代。我们没有为了凑满配额引入 SST 同源评分文本。

### 4.2 各部分希望提供什么能力？

- **CLINC / SGD**：意图匹配、对话状态与动态 schema 理解；SGD 输入只使用当前可见前缀，不读取未来 turn。
- **SNLI / BoolQ / ARC**：语义关系、基于材料的二元判断与知识问答。新增 SNLI 包含 4k 三分类 choice 和 2k“是否蕴含”的 noul；neutral 不被解释为现实命题为假。
- **DBpedia**：学习文本与自身 ontology 的匹配，不改造成 AG News 的新闻四分类。
- **GoEmotions**：只用明确单标签样本做互斥 choice，不将多标签随意取第一项，也不改造成当前 Emotion benchmark 的六类。
- **程序合成**：补充可检查的规则、状态、等级和概率结构，不将无法验证的模型自信程度当作标签。

没有生成式 API 标注、改写、伪标签或教师造题。同一原始案例的排列与视图不被冒充为独立标注来源；新增 30k train 对应 30k 个原始记录/分组身份，但这不是所有样本在语义上绝对不同的证明。

### 4.3 来源隔离与去重

六个外部来源整体禁止进入训练和开发，包括其官方 train/dev、镜像和可追溯派生版本：typed-decisions、AG News、当前 Emotion 来源、Banking77、当前 Prompt Injection 来源、Stanford SST 家族。

新增数据排除 S0 train/dev/test 已使用的案例和相关组。SNLI 按图像/前提来源组、SGD 按对话、CLINC 按文本、BoolQ 按共享 passage 等进行隔离。先分组，再生成决策视图，避免同一原始案例的相关形式跨 train/dev。

实际构建中，一个 GoEmotions 候选与外部测试文本精确重合，已被剔除，再由其他合规案例补足配额。测试内容只用于拒收污染候选，不用于构造器生成样本或挖掘模型难例。

公开文本还经过有界的词法近重复筛查；合成任务按任务族和原始事实排除重复。必须说明，这不是穷尽的语义去重，也不能证明所有上游数据谱系没有交叉。合成的新场景仍来自已有任务家族，不是 family-held-out 测试。

由于这些公开 benchmark 的部分结果在项目过程中已经被观察过，我们称其为 **source-held-out transfer evaluation**，而不是从未观察过的 blind test；基础预训练是否接触过这些公开来源也无法排除。

## 5. 训练协议：只扩数据，不同时换算法

S1 从原始 `qwen3-0.6b-diffusion-mdlm-v0.1` base 初始化，不从 S0 checkpoint 继续训练。“原始 base”指没有接受本项目 S0/S1 监督适配，不是未经训练的神经网络。

| 项目 | 设置 |
|---|---|
| 更新范围 | 全参数训练 |
| 精度 | BF16 参数/前反向路径，损失统计使用 FP32 |
| 训练轮数 | 3 epochs |
| 有效全局 batch | 32，双 GPU DDP |
| 优化器 | AdamW |
| 初始学习率 / 最低学习率 | 2.5e-5 / 1e-6 |
| Weight decay | 0.01 |
| 调度 | 5% warmup，随后 cosine decay |
| 梯度裁剪 | 1 |
| 随机种子 | 42 |
| 最大上下文 | 4,096，不静默截断 |
| Dev 评估 | 每 100 次更新及每轮结束 |
| Checkpoint 选择 | 原 S0 1,000 条 dev 的 mean KL 最低 |

S1 的最长实际训练输入为 1,359 tokens。40k train、有效 batch32、三轮对应 3,750 次更新。另有 2,000 条新增 grouped dev，只用于选定模型后的诊断，不改变选模规则。

训练完整运行三轮；选中的 checkpoint 为 step1,300，dev KL 为 0.26017，重新加载后复算值一致。Epoch1 结束时是 step1,250，dev KL 为 0.26049。本文没有把 step1,300 的外部结果标成 epoch1-end 成绩。

这仍是单随机种子的初步实验。S1 训练曝光量比 S0 大；没有 S0-long 对照，因此无法把差异完全归因于新增来源，而排除更长训练的影响。

## 6. 如何与 Laya 公平地比较？

### 6.1 比较对象是训练后的发布模型

我们使用 Laya 的公开英文发布 checkpoint，本文简称 **Laya base**。这里的 base 是“未在本项目进一步微调”的意思，不意味着它没有经过任务训练。

这是合理的最终模型性能比较。不过，它不是同训练数据、同预算的纯架构比较；Laya 的完整训练过程和数据没有全部公开。其官方 README 明确注明 AG News 在训练混合中，因此 AG News 不能被描述为双方都保持相同来源隔离的测试。

我们没有把使用 typed-decisions 训练集适配的专门 Laya checkpoint 混入这一主表，也不将第三方 Jev 的不同协议分数并入本实验。

### 6.2 对齐可见信息，保留各自原生模型

三者使用相同测试案例、gold、候选项及顺序。DLLM 使用共享 Yes/No；Laya 保留原生决策头。主条件统一为完整输入、温度1；noul 不给 Laya 额外的隐藏判断 rubric。

评测数量固定为：

| 测试集 | 完整决策数 |
|---|---:|
| typed-decisions | 2,000，来自 400 个 case |
| AG News | 7,600 |
| Emotion | 2,000 |
| 原版 Banking77 | 3,080 |
| Prompt Injection | 116 |
| SST5 | 2,210 |
| **外部合计** | **17,006** |

内部 S0 test 的 1,000 条另行报告。所有主评测均完整输出、零丢样本；没有将过去400/600条子集分数与全量分数直接相减。

### 6.3 为什么 Laya 的 Banking77 不是官方表中的 42.5%？

官方文档将低分归因于默认 `head_max_len` 的选项预算：77个标签会被截成极短前缀，部分区别信息消失。我们也实测了这个影响：同一公开模型、同一完整测试集，默认 SDK 输入得到45.13%，保留完整输入得到57.08%。

主表采用57.08%，因为DLLM能看到完整候选，不能让Laya丢失标签信息后再宣称模型本身落后很多。官方42.5%与我们默认45.13%的差异没有逐项复刻，不能全部归因于某一个因素。

与此同时，质量评测的精度仍不完全一致：DLLM为BF16，Laya为FP32。我们披露这个差异，不据此作同精度速度或纯架构结论。

## 7. 主结果：可迁移，但并不全面

### 7.1 完整测试集准确率

本表的S1是step1,300、batch1质量基线；不是后续batch32的轻微数值变体。

| 测试集 | DLLM 原始 base | DLLM-S1 best | Laya base |
|---|---:|---:|---:|
| typed-decisions | 41.35% | **52.25%** | 35.85% |
| AG News | 79.07% | 80.91% | **92.87%** |
| Emotion | 55.65% | 56.35% | **59.50%** |
| Banking77 | 24.09% | **60.49%** | 57.08% |
| Prompt Injection | **82.76%** | 70.69% | 69.83% |
| SST5 | 36.52% | **42.58%** | 35.02% |

对原始MDLM而言，Banking77和typed-decisions有显著的点估计收益，SST5也提高了准确率；但Prompt Injection明显退化。相对Laya，S1在typed-decisions、Banking77、SST5更高，Laya在AG News和Emotion更高。Prompt Injection只有116条，S1仅比Laya多答对1条，不宜过度解读。

在固定checkpoint的配对case bootstrap中，S1减Laya的准确率差异95%区间约为：typed-decisions `[+13.50,+19.05] pp`、Banking77 `[+1.72,+5.13] pp`、SST5 `[+4.98,+10.32] pp`。这些区间使用2,000次重采样，typed-decisions按case保留关联决策；未包含训练seed不确定性，也未进行多重比较校正。

### 7.2 从S0扩到S1，平均成绩没有明显提高

| 测试集 | S0 best | S1 best | S1减S0 |
|---|---:|---:|---:|
| typed-decisions | 50.30% | 52.25% | +1.95 pp |
| AG News | 82.55% | 80.91% | -1.64 pp |
| Emotion | 53.80% | 56.35% | +2.55 pp |
| Banking77 | 61.27% | 60.49% | -0.78 pp |
| Prompt Injection | 71.55% | 70.69% | -0.86 pp |
| SST5 | 43.39% | 42.58% | -0.81 pp |
| **六任务等权平均** | **60.48%** | **60.54%** | **约+0.07 pp** |

因此，这篇文章不能以“四倍数据带来全面提升”为结论。新增监督改变了能力分布，Emotion有恢复，而AG News等任务没有继续受益。

平均方式也会改变排名：S1与Laya的等权平均准确率是60.54%与58.36%；直接池化全部决策后则是65.90%与68.08%，因为7,600条AG News占据很大权重。两者都是描述性汇总，不代表普遍赢家。

## 8. 概率可靠性：比准确率更值得警惕的变化

### 8.1 ECE衡量什么？

ECE比较置信度与实际正确率。本文外部评测沿用15个等宽置信度区间：

$$
\mathrm{ECE}=\sum_{b=1}^{15}\frac{|B_b|}{N}
\left|\mathrm{accuracy}(B_b)-\mathrm{confidence}(B_b)\right|.
$$

下表将ECE乘100，以百分比显示；越低越好。所有条件温度均为1，没有用外部测试拟合温度。它不等价于官方经过温度校准后报告的ECE。

| 测试集 | DLLM 原始 base | DLLM-S1 best | Laya base |
|---|---:|---:|---:|
| typed-decisions | 26.19% | **16.16%** | 30.90% |
| AG News | 19.52% | 12.25% | **4.23%** |
| Emotion | **7.95%** | 23.02% | 30.58% |
| Banking77 | 19.06% | 19.57% | **16.48%** |
| Prompt Injection | **4.07%** | 19.98% | 29.13% |
| SST5 | **4.97%** | 20.77% | 33.58% |

Emotion上S1比原始base的准确率略高，ECE却明显变差。SST5也类似。这意味着模型可以答对更多题，但对一部分错误预测变得更加自信。

### 8.2 NLL提供另一种视角

| 测试集 | DLLM 原始 base | DLLM-S1 best | Laya base |
|---|---:|---:|---:|
| AG News | 0.7015 | 0.8168 | **0.2539** |
| Emotion | **1.3282** | 1.4947 | 2.0146 |
| Prompt Injection | **0.4150** | 0.6790 | 3.2636 |

Laya在Emotion上的准确率最高，但在单位温度下，其NLL和ECE都更差。AG News上，S1相对base准确率与ECE有所改善，NLL却更差，说明不同统计量并不保证同向变化。

反过来，低ECE也不等于高能力。原始base在SST5上的ECE只有4.97%，但准确率只有36.52%；较低的置信度可以使其校准偏差不大，却不能让它正确识别更多样本。我们需要同时报告accuracy、NLL/Brier和ordinal指标，不能单独挑选一个数字。

### 8.3 内部测试的改善不能替代外部迁移

在内部1,000条S0 test上，950条是硬标签，50条是已知分布任务。原始base、S0、S1的硬标签准确率分别为44.11%、87.05%、89.47%；mean KL分别约为1.4660、0.31551、0.28173。

内部提升是真实的，但它与训练来源/任务家族有关。它证明接口适配与已有结构学习有效，不证明所有新来源都得到同等收益。

## 9. 从数据性质解释结果：哪些是观察，哪些是假设？

### 9.1 统一了Yes/No，并没有统一任务语义

Prompt Injection完整测试有60条注入和56条非注入。原始base检出44条注入，并正确识别52条非注入；S1只检出26条注入，却正确识别全部56条非注入。

退化不是随机发生的，而是**误报更少、漏报更多，判断偏向No**。

但S1的硬标签noul并不是No占多数：Yes为4,339条，No为4,069条。简单的类别先验失衡解释不成立。

一个可能原因是，SNLI/BoolQ主要要求判断“给定材料是否支持答案”；注入检测则要求识别一段文本改变系统行为或越过指令边界的意图。它们共享输出形式，却不共享全部判断依据。训练可能强化了较保守的支持性判断，而没有保住另一种边界识别能力。

这仍是假设，不是已证实的因果机制；我们没有做来源消融。并且这里测试的是注入**检测分类**，不能据此宣称模型在生成场景中实际服从了攻击。

### 9.2 “3,000条情绪数据”的有效覆盖并不均匀

实际新增GoEmotions单标签数据中，neutral有1,084条，占36.1%。部分情绪标签的数量如下：

| 标签 | 训练条数 |
|---|---:|
| love | 119 |
| anger | 94 |
| sadness | 73 |
| joy | 70 |
| surprise | 47 |
| fear | 39 |

与当前Emotion六类同名的标签合计只有442条。其他情绪标签也可能提供迁移能力，但不能把整个3,000条都理解为对这六类的均衡直接监督。

此外，GoEmotions来自Reddit评论，采用更细粒度的情绪与态度体系。保持原始标签语义是正确的数据隔离做法，却意味着从来源到目标任务不是直接替代。S1修复了部分S0情绪退化，但没有同时修复概率可靠性。

### 9.3 实体类别匹配不等于新闻主题判断

DBpedia的目标是将实体描述映射到公司、人物、建筑、作品等本体类别；AG News要求综合新闻事件与语境判断主题。同一个公司或人物可以出现在不同主题的新闻中。

S1在新增DBpedia诊断dev上的准确率达到99.75%，但AG News并没有相对S0提升。这表明很好的来源内适配不保证转化为目标任务收益。是否学到了依赖实体身份的捷径，仍需要进一步分析，而不能仅凭这一现象下定论。

### 9.4 全参数硬标签训练缺少原能力保持约束

S1的70%训练决策来自CLINC、SGD、SNLI、DBpedia和BoolQ，20%来自程序合成。监督主体强调标签匹配、显式语义关系和规则验证。

全参数更新能够适配这些任务，也可能改变原有表征。大量硬标签交叉熵鼓励拉开正确项与其他项的分数，但不保证来源外的置信度仍然可靠。我们没有加入显式的原模型行为保持目标；选择dev也仍是S0来源。

这与观察到的“源任务学得更好，而部分外部任务更自信地出错”相容，但不能将所有现象归为已经证实的灾难性遗忘。能力覆盖、数据分布、优化过程和输出尺度都可能参与其中。

## 10. 效率：batch32到底带来多少收益？

### 10.1 匹配的batch1与batch32实验

我们没有用旧的Laya批处理时间直接除以DLLM单条时间，而是为DLLM补充了同代码、同设备、同精度的对照：

- 同一张RTX A6000，同一个S1 best，BF16；
- 六套完整外部测试，共17,006条；
- 每套任务3次不计时预热；
- batch32保持原序连续分组，不按长度排序，右侧padding；
- 除最后一个余数batch外，实际batch均为32；
- 保持完整输入、原始mask位置和原始概率定义。

| 测试集 | Batch1 ms/decision | Batch32均摊 ms/decision | 吞吐提升 |
|---|---:|---:|---:|
| typed-decisions | 25.31 | 9.13 | 2.77x |
| AG News | 25.45 | 4.23 | 6.02x |
| Emotion | 25.86 | 3.07 | 8.42x |
| Banking77 | 25.06 | 15.59 | 1.61x |
| Prompt Injection | 25.92 | 3.92 | 6.62x |
| SST5 | 25.67 | 3.36 | 7.64x |
| **按决策数加权的整体** | **25.44** | **6.61** | **3.85x** |

累计前向时间从432.70秒下降至112.43秒，吞吐从39.30提升至151.26 decisions/s。最大PyTorch peak allocated memory约1.68 GiB，包含驻留权重；它不是CUDA上下文、缓存预留或整个设备的总显存占用。

### 10.2 这不是6.61ms的单请求延迟

计时只包含同步后的backbone、mask位置提取、Yes/No投影和FP32转换，不包含分词、组batch、H2D/D2H传输、CPU softmax、文件I/O以及排队等待。

例如Banking77的一批中位前向时间约498ms，处理约32条决策后才摊成每条15.59ms。长输入使它的吞吐收益小于短输入任务；其padding比例只有约3%，不能把较小收益主要归因于padding浪费。

当前只是每种batch配置一次完整计时，没有重复独立运行得到性能置信区间，也没有宣称已经找到最优batch或kernel。

### 10.3 批处理不是逐位等价的数值变换

BF16 batch32与batch1有72/17,006条argmax变化，约0.42%；六套任务准确率变化都小于0.1个百分点，但最大单项概率差达到0.0773。质量主表仍保留原batch1结果，不能把“平均指标接近”写成“所有输出不变”。

另做384条FP32批处理对照，最大概率差约8.1e-6，零argmax变化。这支持主要差异来自低精度批形状下的数值计算，而不是padding语义错误；它不是全量FP32性能或质量评测。

实现时曾遇到继承模型的二维mask广播兼容问题，最终在评测器中显式使用四维布尔valid-key mask `[B,1,1,L]` 修复。没有改动模型权重、注意力语义或训练算法。

### 10.4 还不能据此宣称比Laya或AR更快

已有Laya计时是FP32、按长度排序、最多batch16，而本次DLLM是BF16、原序batch32。二者不是同配置性能对照。未来若要回答在线延迟问题，应补同精度batch1的p50/p95；若要回答部署吞吐问题，应统一资源约束并记录各自合理优化配置。

更重要的是，本次3.85倍是**同一个DLLM由batch1改成batch32的收益**，不是diffusion相对于AR的收益。

## 11. 这次初步实验提供了哪些insight？

### Insight 1：统一读出接口可以有用，但不保证统一迁移

Shared Yes/No能够在不为每种标签空间设计专用输出头的情况下适配多类任务。显著的Banking77与typed-decisions收益表明这种接口值得继续研究；Prompt Injection退化则说明接口统一不能替代任务语义覆盖。

### Insight 2：数据规模不是有效覆盖的充分条件

从10k增加到40k，平均外部准确率基本持平。新增来源的类别分布、标签语义、难度和与已有数据的重叠，比总行数更能解释收益落在哪里。

### Insight 3：决策模型需要对概率负责

只看accuracy会掩盖重要失败：模型可以维持或提高准确率，同时对错误更加确信。对需要风险阈值、拒答或人工升级的系统，NLL、Brier、ECE和有序误差不是装饰性指标。

### Insight 4：评测协议会实质改变结论

同一Laya模型在Banking77上仅因是否保留完整输入就相差约12个百分点。完整测试还修正了400条子集造成的“AG News完全没有提升”印象。先检查输入信息和样本范围，再讨论模型能力。

### Insight 5：吞吐优化与质量复现必须一起做

batch32带来了明确的实际吞吐收益，也引入可测量的BF16数值差异。把计时口径、样本覆盖和预测变化一起报告，才能让性能数字具有可复现含义。

## 12. 局限与下一步

这是一组早期实验，以下问题还没有解决：

1. **单seed。** 配对样本区间没有覆盖重新训练的不确定性。
2. **缺少S0-long。** 未将新增来源收益与更多训练曝光严格拆开。
3. **缺少匹配的AR对照。** 不能作diffusion优越性结论。
4. **Laya训练条件不对齐。** 它是合理的发布模型参照，但训练预算、覆盖和来源隔离不是相同条件。
5. **能力保持与校准不足。** 没有显式保留原模型能力，也没有使用独立dev开展温度校准研究。
6. **去重和来源审查有边界。** 有界词法筛查不是语义污染证明；公开预训练污染仍未知。
7. **checkpoint追加诊断属于事后分析。** 不能看过外部成绩后换checkpoint，再声称新结果仍是独立测试选优。
8. **速度口径有限。** 目前是前向吞吐，不是端到端服务延迟或跨架构严格基准。

后续值得验证的方向包括：更均衡的独立来源能力覆盖、来源隔离开发集、数据来源消融、S0-long、同规模AR，以及针对独立dev的校准。它们都是待验证计划，不是本文已获得的结论；任何新数据方案都不应根据当前测试逐条错误定向生成训练样本。

## 13. 复现与开源边界

本研究基于继承的Laya代码和外部MDLM checkpoint。我们不将整个SDK、模型架构或上游训练成果宣称为原创。准备开放的是方法增量、数据构建逻辑、训练/评测入口、配置与维护后的汇总结果。

三个版本需要分开记录：

| 用途 | 代码版本 |
|---|---|
| 冻结质量评测 | `fb672477594f29681b90d13ec679819ab8033c5c` |

## 结语

这次实验给了我们一个正面结果，也给了一个更重要的提醒。

正面结果是：一个小型Diffusion LM，可以通过共享Yes/No读出和有限监督，变成能处理动态候选、二元判断和有序评分的实用研究原型。

提醒是：**让模型输出一个概率向量，并不意味着这些概率已经适合做可靠决策。** 能力覆盖、错误置信度、输入预算和数值执行方式，都可能改变系统最终的行为。

因此，我们更愿意将它看作一个可复现的起点：先确认接口能够工作，再认真研究它在什么情况下有效、在什么情况下遗忘，以及什么时候不应该相信它。
