# Shared Yes/No：让 DLLM 直接评估选项

2026-09-24 · 技术博客

代码、训练/测试数据与使用说明：[zhouzihao11/jev-dllm](https://github.com/zhouzihao11/jev-dllm)。

## 1. 动机：把待决策变量表示成待恢复的位置

工具路由、意图识别、条件判断和等级评估，往往都有明确的候选范围。程序提供状态与选项，模型返回概率，后续逻辑据此排序、选择分支或转交人工。这里的核心任务是**理解并比较候选**，而不是生成一段解释。

### 为什么用 DLLM：从顺序生成答案到并行恢复决策变量

常规 next-token 接口把判断放在序列末尾：先将上下文汇集到答案位置，再预测答案 token。当同一个 state 下需要同时决定事件类型、风险等级和下一步动作时，自回归生成通常会把这些变量排成一个序列，后面的决定以先前输出为条件。分别询问也可以，但朴素实现会重复处理相同上下文。

我们希望换一种表示：**不先规定答案的生成顺序，而是把待决策变量直接放进输入，作为一组等待恢复的未知位置。**

$$
\text{Context}+\text{Decision Slots}
\rightarrow\text{Parallel Judgments}.
$$

Masked Diffusion Language Model（MDLM）为此提供了自然接口。多个 mask 各自拥有上下文表示，通过双向注意力读取完整 state、question 和候选集合，并在同一次前向中形成判断。其去噪形式还为后续迭代修正提供了空间：先得到局部判断，再利用它们继续更新其他位置，而不必沿用固定的从左到右输出顺序。

因此，选择 DLLM 的动机不只是更快地做分类，而是探索一种**并行、可修正的决策表示**。本文先用约 0.6B 的 [Qwen3 MDLM](https://huggingface.co/dllm-hub/Qwen3-0.6B-diffusion-mdlm-v0.1) 验证单题、单次前向的起点；多问题协调和多步修正尚未验证。AR 也可设计并行读出接口，本文不据此宣称 DLLM 已优于所有 AR 决策方案。

### 为什么 Shared Yes/No：候选各自表示，判断函数共享

选择 mask 表示后，仍有第二个问题：用一个答案 mask 预测 `A/B/C`，还是给每个候选一个位置？

单 mask 预测编号，仍会把整题汇集到一个答案表示，并用不同的词表输出向量 $W_A,W_B,W_C$ 区分类别。同一个候选从 A 换到 B，语义没有改变，却绑定到了另一组输出权重。这是与候选语义无关的 identifier 偏差的一个可能来源。

Shared Yes/No 将候选差异放进各自的表示 $h_i$，让所有候选共享同一个 Yes-minus-No 读出方向 $W_{\mathrm{Yes}}-W_{\mathrm{No}}$。也就是从“一个答案表示 + 多个编号专属读出”，改为“多个候选表示 + 一个共享语义读出”。选择 DLLM 回答的是**如何组织决策变量**，共享 Yes/No 则回答**如何对候选使用一致的评分函数**。

## 2. 方法：每个选项一个 mask，共享 Yes/No 读出

我们把状态、问题和候选描述放在同一条输入中，每个候选后设置一个决策 mask：

```text
State:
库存剩余 8 件，订单需要 3 件。

Question:
下一步应执行什么操作？

直接安排发货: [MASK]
因缺货取消订单: [MASK]
请求补充商品数量: [MASK]
```

模型在每个 mask 位置读取同一对 Yes/No 词表权重。候选分数取两者的 logit 差，对互斥候选再做题内 softmax：

$$
s_i=z_i^{\mathrm{Yes}}-z_i^{\mathrm{No}},
\qquad
p_i=\frac{\exp(s_i)}{\sum_j\exp(s_j)}.
$$

候选身份由输入文本与位置表达，不再分别绑定到 A/B/C 的输出向量。增加候选只需增加描述和 mask，输出权重保持共享；这并不意味着模型天然不受候选顺序影响。

同一个读出支持三种接口：

- **choice**：题内 softmax，返回动态候选的概率。
- **noul**：单 mask，用 Yes-minus-No 的 sigmoid 返回命题成立概率。
- **score**：对有序等级归一化，返回等级分布及期望值。

训练使用交叉熵，score 额外加入权重为 0.25 的 normalized RPS，利用等级顺序约束概率分布；损失按 decision 归一化。推理时只计算所需位置的 Yes/No 投影，**一次前向得到整题分数，不进行多步去噪**。即使有 77 个候选，也不是分别运行 77 次模型。

## 3. 实验：从 10k 扩充到 40k 决策

我们从 10k 决策的 S0 起步，保留其训练数据并增加 30k，得到 S1。S0 中公共数据与程序合成的比例为 70% / 30%，S1 为 **80% / 20%**。

S1 的公共来源包括 CLINC 5k、SNLI 9k、ARC 1k、SGD 4k、DBpedia 6k、GoEmotions 3k、BoolQ 4k；其余 8k 是可验证的约束、状态、等级与已知概率机制任务。沿用已有标注和程序验证，**不调用生成式 API 标注或改写**。

各来源保留自己的标签语义，按原始案例分组与去重。六套外部测试来源及其可追溯派生版本不进入本项目监督训练，用于评估跨来源迁移；这不等于保证基础预训练从未接触过这些公开数据。

S1 从原始 MDLM base 全参数训练三轮，使用 BF16、有效 batch 32、AdamW 和峰值学习率 2.5e-5。按原 S0 开发集 mean KL 选择 checkpoint，主结果来自 **step 1,300**，不是 epoch 1 结束的 step 1,250。完整配方与命令见[仓库 README](https://github.com/zhouzihao11/jev-dllm#readme)。

### 完整测试集准确率

比较统一使用完整状态、相同候选与顺序，温度固定为 1。DLLM 使用 BF16、batch1；[Laya](https://github.com/NandhaKishorM/laya) 使用其公开发布模型、原生决策头和 FP32 动态 batching。

| 测试集 | 决策数 | MDLM base | Shared Yes/No · S1 | Laya base |
|---|---:|---:|---:|---:|
| typed-decisions | 2,000 | 41.35% | **52.25%** | 35.85% |
| AG News† | 7,600 | 79.07% | 80.91% | **92.87%** |
| Emotion | 2,000 | 55.65% | 56.35% | **59.50%** |
| Banking77 | 3,080 | 24.09% | **60.49%** | 57.08% |
| Prompt Injection | 116 | **82.76%** | 70.69% | 69.83% |
| SST5 | 2,210 | 36.52% | **42.58%** | 35.02% |

† Laya 官方说明 AG News 属于其训练混合来源。这是发布模型的性能对照，不是同训练数据、同预算的架构比较。Laya 使用不截断候选的完整输入，而不是官方默认短输入预算。

S1 在 Banking77、typed-decisions 和 SST5 上获得了明显的准确率收益，但 Prompt Injection 退化。扩充也没有带来全面提升：S0 与 S1 的六任务等权平均准确率分别为 **60.48% 和 60.54%**。

### 校准：准确率之外，还要看置信度

ECE 衡量预测置信度与实际正确率的偏差。以下使用 15 个等宽置信度区间，以百分比显示，**越低越好**；未额外拟合温度。

| 测试集 | MDLM base | Shared Yes/No · S1 | Laya base |
|---|---:|---:|---:|
| typed-decisions | 26.19% | **16.16%** | 30.90% |
| AG News | 19.52% | 12.25% | **4.23%** |
| Emotion | **7.95%** | 23.02% | 30.58% |
| Banking77 | 19.06% | 19.57% | **16.48%** |
| Prompt Injection | **4.07%** | 19.98% | 29.13% |
| SST5 | **4.97%** | 20.77% | 33.58% |

Emotion 的准确率略有提高，但 ECE 明显变差。反过来，原始模型在 SST5 上 ECE 很低，准确率却只有 36.52%。因此，低 ECE 不等于高能力，准确率提高也不代表概率变得更可靠。我们同时记录 NLL、Brier 和有序误差，避免只看单一指标。

### 批处理吞吐

在同一张 RTX A6000、BF16 和同一 S1 checkpoint 上，batch32 将 17,006 条外部决策的均摊前向耗时从 **25.44 ms 降至 6.61 ms**，吞吐从 39.30 提升到 151.26 decisions/s，约 **3.85 倍**。这不包含分词、传输与排队，不是单请求延迟，也不是相对 Laya 或 AR 的加速比。BF16 批处理有约 0.42% 的 argmax 变化，质量主表仍采用 batch1。

## 4. 两个问题：能力覆盖与过置信

### 训练数据未必覆盖对应的下游能力

共享输出形式，不代表任务需要相同的判断依据。CLINC/SGD 的意图匹配容易与 Banking77 建立联系；BoolQ/SNLI 的阅读理解和蕴含判断，却不能直接替代指令注入识别。GoEmotions 虽然提供情绪监督，但标签体系和文本风格不同，当前采样中 neutral 又占 36.1%，有效覆盖并不均衡。

全参数训练会调整共享表示，新监督可能强化某些判断，同时干扰没有被充分覆盖的原有能力。Prompt Injection 的下降与这种解释相容，但还需要来源消融验证。**扩充应关注能力覆盖，而不只是增加行数。**

### 缺少额外校准约束，可能出现过置信

当前主要使用硬标签交叉熵，没有额外加入校准或原模型分布保持目标。训练可能拉大候选间的分数差，使模型对错误预测也更加自信。准确率只关心第一名是谁，ECE 还关心模型给了第一名多高的概率，所以两者可能反向变化。

交叉熵本身已是概率评分目标，并不是“没有优化概率”；但有限样本上的拟合不保证跨来源校准。Emotion 就体现了这个问题：准确率从 55.65% 变为 56.35%，ECE 却从 7.95% 升至 23.02%。后续应比较不同概率损失、分布保持项及独立开发集上的温度校准，而不是假定加一个 loss 就必然解决问题。校准也不能单独修复没有学会的任务能力。

## 5. 结语

Shared Yes/No 的核心是：**候选由自然语言描述，每个候选拥有自己的位置，所有位置共享 Yes/No 判断函数，结果以概率交给程序。** 这次初步实验验证了小型 DLLM 做单次前向结构化决策的可行性，也揭示了迁移与校准并非自动获得。

下一步重点是更有效的数据覆盖与更可靠的概率输出。多步决策修正和同一 state 下的多问题联合建模，是进一步的探索方向，尚不是本实验已经验证的能力。
