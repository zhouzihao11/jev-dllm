## 结论边界与复现

- 在上述 15 行的逐套 ACC 描述中，S1 高于 Kev 10 项、Kev 高于 S1 4 项、1 项持平；这不是统计显著性检验或总体排名。
- S1 的 Nimble9 平均 ACC、ECE、Brier 更好，Kev 的平均 NLL 更好。Kev 在 Jabr 和 MASSIVE de-DE 更强，部分任务 NLL 更低，但不是所有准确率或校准指标都改善；例如 SummEval consistency 和 PubMedQA 的 ACC 明显较低。
- ContractNLI 的共同集 S0 ACC 为 61.19%，高于 S1/Kev。全部 2,074 条 unsupported 计错时，base/S0/S1/Laya/Kev ACC 分别为 40.45/54.29/48.70/42.96/49.23%；不能把共同集分数当作全部尝试结果。
- Backbone 0.6B/0.8B、训练数据、预测头、renderer、精度与温度不等。本比较不支持架构因果归因，也不支持匹配吞吐优势。Kev 使用未优化的 FP32 reference causal_conv1d/gatedDeltaRule kernels，耗时口径与 DLLM 不同，不发布公平性能比值。
- 研究记录中 51 条 Core smoke 全部成功，直接原生编码/forward 与适配器概率最大差为 0。这是历史 native parity，不是本地发布迁移重新验证。本任务未访问服务器、下载模型、安装环境或执行 ML 测试。

可选 Kev 准备及独立推理环境见 [Kev 复现流程](../benchmark/KEV.md)；Core 数据准备沿用[公开 Core 流程](benchmark_core.md)。根 README 的默认安装、S1 quickstart 和 HTTP 服务不变，Kev 不要求启动完整上游 serve。旧版四模型、内部测试和官方 HTTP 数值仍保留在[完整实验表](experiment_results.md)，不要给其已排除来源或未测协议补填 Kev 值。
